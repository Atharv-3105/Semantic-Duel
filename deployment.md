# 🚀 Semantic-Duel — Free-Tier Deployment Plan

> Deploy a Go WebSocket game server + React frontend using **$0/month** infrastructure.

---

## Architecture Overview

```
                    ┌──────────────────┐
                    │   Vercel / CF    │
                    │   (Frontend CDN) │
                    └────────┬─────────┘
                             │ wss://
                    ┌────────▼─────────┐
                    │  Render / Fly.io │
                    │  (Go + WebSocket)│
                    ├──────────────────┤
                    │ data/            │
                    │  embeddings.npy  │
                    │  vocabulary.json │
                    └──────────────────┘
```

| Component | What | Free-Tier Platform |
|---|---|---|
| **Frontend** | React/Vite static build | Vercel, Cloudflare Pages, or Netlify |
| **Backend** | Go binary + WebSocket server | Render, Fly.io, or Railway |
| **Embeddings** | `vocabulary.json` + `embeddings.npy` (~5 MB) | Bundled into the backend Docker image |

> **Important:** WebSocket support is critical for this project. Not all free-tier platforms handle persistent WebSocket connections well. The options below are specifically chosen for WebSocket compatibility.

## Step 1: Create the Dockerfile

Create this at the project root:

```dockerfile
# ── Stage 1: Build the Go binary ──
FROM golang:1.24-alpine AS builder

WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download

COPY cmd/ cmd/
COPY internal/ internal/

RUN CGO_ENABLED=0 GOOS=linux go build -o /server ./cmd/server

# ── Stage 2: Minimal runtime image ──
FROM alpine:3.20

RUN apk --no-cache add ca-certificates

WORKDIR /app

# Copy the compiled binary
COPY --from=builder /server .

# Copy pre-computed embeddings (generated by scripts/precompute.py)
COPY data/ data/

EXPOSE 8080

CMD ["./server"]
```

> The embeddings (~5 MB) are baked into the Docker image so there's no need for persistent storage. The final image size is ~25 MB.

## Step 2: Deploy the Backend

Choose **one** of the three options below:

---

### Option A: Render (Easiest Setup) ⭐ Recommended for Beginners

**Free tier:** 750 hours/month, auto-sleep after 15 min inactivity, WebSocket support.

| Pros | Cons |
|---|---|
| Dead simple setup from GitHub | Sleeps after 15 min inactivity (~30s cold start) |
| Auto-deploy on push | 512 MB RAM limit |
| Built-in HTTPS + `wss://` | Can be slow on free tier |
| No credit card required | |

#### Steps:

1. **Push your code** to GitHub (including `data/` directory)

2. **Go to [render.com](https://render.com)** → New → Web Service

3. **Connect your repo** → `Atharv-3105/Semantic-Duel`

4. **Configure:**

   | Setting | Value |
   |---|---|
   | Name | `semantic-duel-server` |
   | Region | Oregon (US West) or closest to you |
   | Runtime | Docker |
   | Instance Type | Free |
   | Health Check Path | `/health` |

5. **Environment Variables:**
   ```
   SERVER_PORT=8080
   GAME_DURATION_SECONDS=60
   RATE_LIMIT_SECONDS=1
   ```

6. **Deploy** → Render builds your Docker image and deploys.

7. **Your backend URL:** `https://semantic-duel-server.onrender.com`

> **Warning:** Render free tier sleeps after 15 minutes of no traffic. The first WebSocket connection after sleep takes ~30 seconds. To keep it alive, use a free cron pinger like [UptimeRobot](https://uptimerobot.com) hitting `/health` every 14 minutes.

#### Keep-Alive Setup (UptimeRobot):
1. Create free account at [uptimerobot.com](https://uptimerobot.com)
2. Add HTTP monitor → `https://semantic-duel-server.onrender.com/health`
3. Set interval to **5 minutes**
4. This prevents the service from sleeping

### Option B: Fly.io (Best for WebSockets) ⭐ Recommended for Production-Quality

**Free tier:** 3 shared-cpu VMs, 256 MB RAM each, 3 GB persistent storage, always-on.

| Pros | Cons |
|---|---|
| **Always-on** (no cold starts) | Requires credit card for signup |
| Native WebSocket support | Slightly more complex setup |
| Global edge deployment | 256 MB RAM per machine |
| Built-in metrics & logs | |

#### Steps:

1. **Install flyctl:**
   ```bash
   # Windows (PowerShell)
   pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"

   # Or via npm
   npm install -g @anthropic-ai/fly
   ```

2. **Sign up & login:**
   ```bash
   fly auth signup
   fly auth login
   ```

3. **Create `fly.toml`** in the project root:
   ```toml
   app = "semantic-duel"
   primary_region = "iad"  # US East (or "bom" for Mumbai)

   [build]
     dockerfile = "Dockerfile"

   [env]
     SERVER_PORT = "8080"
     GAME_DURATION_SECONDS = "60"
     RATE_LIMIT_SECONDS = "1"

   [http_service]
     internal_port = 8080
     force_https = true
     auto_stop_machines = "off"    # Keep always-on for WebSockets
     auto_start_machines = true
     min_machines_running = 1

     [http_service.concurrency]
       type = "connections"
       hard_limit = 100
       soft_limit = 80

   [[http_service.checks]]
     grace_period = "10s"
     interval = "30s"
     method = "GET"
     path = "/health"
     timeout = "5s"
   ```

4. **Deploy:**
   ```bash
   fly launch --no-deploy    # First time: creates the app
   fly deploy                # Build and deploy
   ```

5. **Your backend URL:** `https://semantic-duel.fly.dev`

6. **Monitor:**
   ```bash
   fly logs          # Live logs
   fly status        # Machine status
   fly dashboard     # Web dashboard
   ```

## Step 4: Connect Frontend → Backend

The frontend reads the WebSocket URL from the `VITE_WS_URL` environment variable. This is set during the **build step** of your frontend deployment.

> **Important:** The WebSocket URL must use `wss://` (not `ws://`) because all free-tier platforms enforce HTTPS.

```
VITE_WS_URL=wss://<your-backend-domain>/ws
```

**Examples:**

| Backend Platform | WebSocket URL |
|---|---|
| Render | `wss://semantic-duel-server.onrender.com/ws` |
| Fly.io | `wss://semantic-duel.fly.dev/ws` |
| Railway | `wss://semantic-duel-production.up.railway.app/ws` |

After setting this, **redeploy** the frontend so the new env var is baked into the build.

## Step 5: CORS Configuration

The WebSocket upgrader already allows cross-origin requests:

```go
// internal/ws/handler.go
var upgrader = websocket.Upgrader{
    CheckOrigin: func(r *http.Request) bool {
        return true  // Allows all origins
    },
}
```

For production hardening, restrict `CheckOrigin` to your actual frontend domain:
```go
CheckOrigin: func(r *http.Request) bool {
    origin := r.Header.Get("Origin")
    return origin == "https://semantic-duel.vercel.app"
}
```

## Troubleshooting

| Issue | Cause | Fix |
|---|---|---|
| WebSocket won't connect | Using `ws://` instead of `wss://` | Use `wss://` — all platforms enforce HTTPS |
| Cold start takes 30s+ | Render free tier sleeping | Set up UptimeRobot pinger |
| "Failed to load embeddings" | `data/` not in Docker image | Ensure `COPY data/ data/` is in Dockerfile |
| CORS errors | Frontend/backend on different domains | Already handled — `CheckOrigin` returns true |
| Connection drops after 60s | Platform WebSocket timeout | Ping/pong heartbeat already implemented (60s) |
| Build fails on Render | Missing `go.sum` | Run `go mod tidy` locally and commit `go.sum` |

## Deployment Order

```
1. Generate embeddings locally     →  python scripts/precompute.py
2. Commit data/ to repo           →  git add data/ && git commit
3. Deploy Backend (Render/Fly.io) →  Push to GitHub or fly deploy
4. Copy backend URL               →  https://semantic-duel-server.onrender.com
5. Set VITE_WS_URL in frontend    →  wss://semantic-duel-server.onrender.com/ws
6. Deploy Frontend (Vercel)       →  Push triggers auto-deploy
7. Set up UptimeRobot pinger      →  Monitor /health every 5 min
8. ✅ Live!
```

> ```bash

> go run ./cmd/server
>
> # Terminal 2: Frontend
> cd frontend && npm run dev
> ```
